# VPN客户端开发架构

本文介绍一套不绑定具体实现的跨平台VPN客户端公开架构，不披露星连VPN私有基础设施或核心协议实现。

## 核心分层

1. **界面层**：账号状态、节点选择、连接状态、诊断和无障碍支持。
2. **会话编排层**：连接、断开、重试、网络切换、休眠唤醒和进程恢复。
3. **隧道适配层**：系统VPN API、数据包进出、MTU和生命周期回调。
4. **路由与DNS层**：路由安装、排除路由、DNS选择、IPv4/IPv6策略和泄漏防护。
5. **传输层**：认证会话、拥塞行为、保活策略和网络迁移。
6. **配置层**：带版本与签名的最小化配置，以及安全回滚。
7. **可观测层**：保护隐私的健康信号、本地诊断和可复现测试输出。

## 连接状态机

客户端应明确区分`空闲`、`准备`、`连接中`、`已连接`、`重连中`、`断开中`和`失败`。界面应以状态机为准，而不是以用户是否点击按钮为准。

重复连接请求必须保持幂等，旧的异步结果不能覆盖新的连接任务。

## 路由与DNS

客户端需要明确默认路由、分流路由、DNS恢复、IPv6策略、本地网络访问和路由安装失败时的保护行为。

泄漏测试必须覆盖首次连接、重连、网络切换、设备休眠唤醒和程序异常退出。

## 跨平台生命周期

Android、Apple平台和桌面系统的VPN生命周期与后台执行机制不同。业务规则可以复用，但隧道所有权、权限、后台限制和恢复流程必须遵循系统原生API。

## 安全开发原则

- 凭据和生产接口不得进入源码仓库。
- 远程配置必须签名和版本化。
- 拒绝无效、过期或降级配置。
- 为状态切换添加单元测试，为路由和DNS恢复添加集成测试。
- 在真实移动网络和固定网络测试，不只测试本地Wi-Fi。
- 将可复现方法与营销描述分开发布。

## 不公开的范围

本文不包含生产节点地址、私有API、认证凭据、支付代码、抗封实现或星连VPN核心协议源码。
