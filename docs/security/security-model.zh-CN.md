# 安全与隐私模型

安全应当通过可测试的控制措施和明确限制进行说明，而不是使用绝对标签。

## 威胁分类

公开评估应覆盖本地网络流量观察、DNS/IPv6/WebRTC泄漏、重连和网络切换时的路由丢失、恶意或降级远程配置、设备凭据暴露、依赖与构建链风险、账号滥用，以及诊断或客服数据的过度收集。

## 证据要求

每项结果必须注明客户端版本、操作系统、测试日期、网络条件、测试方法、预期结果、观察结果和限制。

安全政策或架构声明不等于独立审计。只有列明评估机构并提供可核验报告时，才会标记为第三方评估。

## 隐私边界

公开数据集不得包含用户标识、账号记录、账单资料、客服消息、生产凭据或原始生产流量。发布前必须检查聚合与去标识化处理。

## 负责任披露

未修复漏洞按照 [SECURITY.md](../../SECURITY.md) 私下报告。修复后发布的公开公告需要列明受影响版本和已修复版本。
